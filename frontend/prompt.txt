## 📌 1. KONTEKST PROJEKTU I ZAŁOŻENIA BIZNESOWE

**Cel aplikacji:**
Aplikacja proponuje użytkownikowi dwie alternatywne trasy między punktem A i B:
1. **Najszybszą** (np. rowerem lub komunikacją miejską).
2. **Zdrową** (maksymalizującą ruch: kroki i kalorie, np. dłuższy spacer przez parki).
TUTAJ JEDNAK BĘDZIE SUWAK w którym możesz wybrać sobie ilość kroków możliwą

**Symulacja "AI Agenta":**
Aplikacja udaje inteligentnego asystenta zintegrowanego z kalendarzem. Użytkownik może ustawić:
- `modes` (środki transportu: pieszo, rower, komunikacja),
- `time_budget_minutes` (np. "Mam tylko 30 minut").
Backend analizuje te dane i automatycznie wybiera najlepszą trasę (`selected_route_id`) oraz dodaje ostrzeżenia (`warnings`), jeśli trasa "zdrowa" przekracza budżet czasowy.

**Tryb Demo:**
Nie ma prawdziwego logowania. Użytkownik klika "Zaloguj jako demo" i zawsze dostaje tego samego, hardcoded'owego usera z celem kroków/kalorii.

## 🧠 3. ARCHITEKTURA STANU (ZUSTAND)

Store musi implementować następującą logikę czyszczenia i automatyzacji:

### A. State Clearing (Czyszczenie przy zmianie punktów)
Gdy użytkownik zmieni `origin` lub `destination` (poprzez wyszukiwarkę lub kliknięcie w mapę), akcje `setOrigin` / `setDestination` **MUSZĄ** wyzerować:
- `plan = null`
- `selectedRouteId = null`
- `routeGeoJsonCache = {}`
*Dlaczego?* Zapobiega to wyświetlaniu starej, nieaktualnej trasy na mapie po zmianie punktów.

### B. Auto-Select & Fetch (Automatyczne rysowanie trasy)
Po otrzymaniu `MapPlanResponse` z endpointu `/map/plan`, store **MUSI**:
1. Ustawić `selectedRouteId = response.selected_route_id`.
2. Natychmiast wywołać akcję pobierającą GeoJSON dla tej trasy (`fetchGeoJson(selectedRouteId)`).
*Dlaczego?* Mapa nie może być pusta po kliknięciu "Planuj". Backend sam decyduje, która trasa jest domyślna (np. jeśli zdrowa przekracza budżet czasowy, wybierze najszybszą).

### C. Map Click State Machine
Stan musi zawierać `mapClickTarget: 'origin' | 'destination' | null`.
- UI musi posiadać dwa przyciski/toggles: *"Kliknij mapę, aby ustawić START"* i *"Kliknij mapę, aby ustawić CEL"*.
- Po kliknięciu w mapę i ustawieniu punktu, `mapClickTarget` **MUSI** zresetować się do `null`.

## 🗺️ 4. ZASADY RENDEROWANIA MAPY (REACT-LEAFLET)

1. **GeoJSON Rendering:**
   Używaj komponentu `<GeoJSON key={selectedRouteId} data={geoJsonData} />`.
   *KRYTYCZNE:* Zmiana `key` przy zmianie trasy wymusza na React odmontowanie starej warstwy i narysowanie nowej. Zapobiega to nakładaniu się wielu tras na mapie.
2. **BBox Conversion:**
   Backend zwraca `bbox` w formacie `[min_lon, min_lat, max_lon, max_lat]`.
   Leaflet wymaga `[[min_lat, min_lon], [max_lat, max_lon]]`.
   Stwórz utility `bboxToLeafletBounds(bbox)` i użyj go do `map.fitBounds()` po zaplanowaniu trasy.
3. **Kolory tras:**
   - `fastest`: Niebieski (`#2563eb`)
   - `healthy`: Zielony (`#16a34a`)
   - `balanced`: Pomarańczowy (`#f59e0b`)
4. **Mobile First:**
   Panel boczny z trasami musi być responsywny (na mobile jako wysuwana szuflada od dołu / bottom sheet), aby nie zasłaniał mapy. Mapa musi zajmować pełną wysokość ekranu (`100dvh`).

## 🔌 5. KONTRAKTY API (JAK ROZMAWIAĆ Z BACKENDEM)

**Base URL:** `http://127.0.0.1:8000/api/v1`
**Content-Type:** `application/json` (dla POST/PATCH)

### 5.1 Auth & User

#### `POST /auth/demo`
- **Request:** `{}` (pusty body)
- **Response:** `{ token: string, user: User }`
- **Akcja:** Zignoruj `token`. Zapisz `user` w Zustand.

#### `GET /me`
- **Response:** `User`
- **Akcja:** Wywołaj przy ładowaniu strony, aby przywrócić stan usera.

#### `PATCH /me/goal`
- **Request:** `{ target_steps?: number, target_calories?: number, prefer_green_routes?: boolean }`
- **Response:** `{ ok: boolean, user: User }`
- **Akcja:** Nadpisz obiekt `user` w store nowym z odpowiedzi.
